# Team27 正式 MWORKS 下载步骤

## 1. 安全准备

1. 四个驱动轮全部架空并固定车体。
2. 一人守住总电源，准备立即断电。
3. 首次测试关闭 `Run on boot`，不得直接放到赛道。

## 2. 在 MWORKS 打开正式模型

先完整退出旧的 MWORKS 会话，再打开根目录的 `package.mo`。不要单独打开控制器文件；加载成功后，用户模型树中应出现 `Controller` 子包。然后打开：

- `Controller/ObsAvoidController_Team27_MWorks.mo`
- `for_code_JGB520_Team27.mo`

正式控制器必须能看到 `5-US Continuous` 单状态 Sysblock 图，不能出现避障算法 CCaller。执行模型检查，确认无错误后再执行 MWORKS 代码生成。

若正式顶层中央仍显示红色大叉，说明当前会话仍缓存了旧包结构。关闭 MWORKS 后重新打开 `package.mo`；正常情况下中央组件类型应为 `Controller.ObsAvoidController_Team27_MWorks`，不应显示为普通 `subSystem`。

## 3. 打开赛会外部模式工具

使用仓库 `Sysblock 外部模式工具/ExternalMode`，硬件选择 `Raspberry Pi`。根据工具界面填写：

- Device Address：树莓派 IP。
- Username / Password：树莓派实际账户。
- Build directory：树莓派上的独立目录，例如 `/home/pi/team27_mworks`。
- Build action：首次选择 `Build`，不要选择运行。
- Run on boot：首次必须取消。
- Communication Interface：`TCP/IP`。
- Port：默认配置为 `17725`，若现场配置不同以实际为准。

先完成 `Build`。该过程必须由 MWORKS 外部工具传输并编译，不得手动修改生成后的 C 文件。

## 4. 架空运行

编译通过、车轮仍架空时，才把 Build action 改为 `Build and run`。

按顺序检查：

1. 遮挡确认通道：`dis1前中、dis2右前、dis3正右、dis4正左、dis5左前`。显示名称已改成对应物理位置。
2. 无障碍时速度目标为 `160`，转角为0；原顶部舵机必须始终保持0，不能再往返扫描。
3. 正前保持大于30 cm，单独把左前缩短到约18～21 cm而右前保持开阔，应提前右转；反向测试应提前左转。方向需连续确认约0.10 s，不能因单次跳变立刻翻转。继续缩短到约12 cm时应达到至少约0.56 rad强转，而不是因正前开阔保持小角。
4. 正前约24～25 cm放置软障碍：左侧瓶颈空间更大应左转，右侧瓶颈空间更大应右转；近似同分时按顺时针采用右转。即使某个前斜向显示很远，只要同侧横向小于8 cm，也不得驶入该侧。
5. 单独把正左或正右侧距缩短到约3～4 cm，车辆必须立即向相反方向打角。再保持正前约35 cm、左右前约18 cm，同时把两侧缩短到约3～4 cm，车辆必须以约 `90 RPM` 直行离开平行边界，不得停死、倒车或左右抖动；若任一前斜向低于12 cm或正前低于18 cm，则不得套用这项走廊释放。
6. 单独把左前缩短至 `4.5 cm` 内且右侧扫掠路径安全，车辆必须先以约 `45 RPM` 向右满幅转离；右前单独受阻时对称处理。确认45 RPM在地面上能稳定起步，若只响不走再回调50 RPM。前 `0.45 s` 内撤走障碍不得倒车；若极近读数持续约 `0.45 s`，车辆应进入有限倒车。正前有效原始值不大于 `5.5 cm` 时同样先转后退；`6 cm` 以上的普通单前角弯道不得误触发这条延迟倒车。
7. 倒车退出并停稳后改变左右障碍位置，车辆必须按当前位置重新选路，不能沿用倒车前方向。正前超过30 cm且原阻挡侧前斜向超过26 cm后应逐渐回正，不允许持续满舵形成调头。停止外部模式后两电机必须归零。
8. 用软障碍同时把左右前保持在 `11 cm` 内，即使正前射线仍显示约30～40 cm空隙，车辆也必须经过约 `0.10 s` 确认后停车回中 `0.20 s`，随后以 `-55 RPM` 先直退 `0.20 s`。如果前方评分判定未来应向右绕，倒车阶段前轮应向左打约 `0.38 rad`；未来应向左绕时对称处理。倒车至少持续 `0.80 s`，三路前向恢复安全后才可退出，绝对上限为 `1.20 s`。
9. 再测试正前约 `16 cm`、左右前约 `14 cm`、左右侧约 `6 cm` 的紧凑停止场景。它不属于双前角口袋，但两条扫掠路径均不可行，应在连续零速约 `0.20 s` 后自动进入带方向倒车。保持障碍不动，第一次倒车后仍卡住时应允许第二次；第二次结束后若障碍仍未解除，则必须保持停车，禁止第三次连续盲倒。将三路前向完全放空后，两次额度应清零。正前数据无效时始终只能停车。
10. 在车头前约 `15～20 cm` 放置窄纸板竖边，从左向右连续横扫三路前向探头的整个覆盖区；任意位置都应至少有 `dis5/dis1/dis2` 一路低于 `20 cm`。若出现三路同时放空的角度，先把左右前探头向正前收拢，再重复检查。真实波束间隙不能靠控制算法补偿。

## 5. 低速落地

架空检查全部通过后，先用2–3 m空旷区域和软障碍物落地测试。当前前进速度层级为 `160/140/130/110/100/90/70/60/45/0 RPM`，有限倒车为 `-55 RPM`；正前提前决策/强转/急停为 `26/12/5.5 cm`，前斜向提前决策为 `22 cm`，方向释放为正前 `30 cm` 配合原阻挡侧前斜向 `26 cm`。通道门槛为前斜向 `9 cm`、横向 `8 cm`，避障最终限幅 `±0.58 rad`，倒车舵角 `±0.38 rad`，每50 ms最大转角变化 `0.16 rad`。任何修改都只能回到正式MWORKS模型重新生成与部署。

## 禁止事项

- 禁止使用生成后的 C 文件作为算法修改入口。
- 禁止使用自制 `team27_main.c`、SSH/SCP 脚本替代正式外部工具下载。
- 禁止首次测试启用开机自启动。
- 禁止未架空车轮直接执行 `Build and run`。

## 已知的新版编译兼容点

原版压缩包在 `rasInit()` 的失败分支中使用了 `int` 返回类型配空 `return;`，新版 2026a 远端 C++ 编译器会因此报 `return-statement with no value`。当前工程只把该失败返回改为 `return 1;`，用于通过新版编译；控制算法、电机换算、串口协议、GPIO 与测距逻辑均未借此修改。该行不是避障算法的一部分，但与原压缩包并非逐字节一致。若赛会要求连这类编译兼容修正也不得存在，应先向技术人员确认官方 2026a 修正版，不能直接恢复后带着已知编译错误上场。
